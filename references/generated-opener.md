# 动态开场与接片

适用于“完整视频加一个生成式开场”、为已有历史长片补动态镜头。生成授权仍以当前可信用户请求及 [视频确认规则](video-approval.md) 为准。

## 设计能听懂的一个动作

先读当前开篇口播、对应字幕 cue 和音轨时钟，再决定镜头时长。选择第一段中能直接看懂的动作，例如车驾离城、守门人关门、军令送到；写清主体、起止状态、方向及为何需要运动。一个短镜头只承载一个主要变化，不因模型支持较长时长而延长旁白或循环镜头。

沿用同项目已验收的全幅分镜作为首帧。固定人物身份、站位、服饰、关键道具和绘画材质；微小跟拍或稳定机位通常比大幅绕拍更容易保持手绘人物连续。字幕与准确中文在后期叠加，提示词不要求模型写片名。保留不遮脸的片名区及既有字幕安全区。

设计稿分别记录：对应口播、实际使用区间、参考图及哈希、主体动作、镜头运动、连续性约束和禁项。人物相貌和具体环境是历史情景示意，不能把设计中的细节写成史料。

## 按真实能力调用

优先当前可调用的专用 API 或工具；现有服务仅有登录网页时，用已启用的浏览器工具及其文档支持的方法。先读取当次服务的模型、分辨率、帧数、质量档、步数、种子和参考输入方式。旧任务参数只作线索，不能当作当前可选值。

形成一份具体请求记录，绑定已审参考、用户的真实授权文字及尝试上限；默认一次提交。明确区分计划参数、实际输入控件和任务生效参数。若服务会改写提示词，检查有效文本是否保留动作、角色与风格；不可见字段标为未知，不复制计划冒充已核验。不要把“用户已登录”单独当作新任务的生成授权，它只恢复先前已授权任务的访问。

提交后保存任务号，状态未知时查原任务。获取 completed 结果和原生文件；登录失效时恢复访问，不能通过提取会话凭证绕过正常入口。浏览器素材清单落后于任务状态时，可用当前已观察到的下载链接及受支持的下载方法；不选取旧任务同名素材。

原文件内若有模型执行元数据，可用 ffprobe 核对模型、参考节点与数值，不要求每个服务都有这类元数据。服务实际输入文件哈希不可见时，保留本地文件哈希、真实上传记录、参考名与首帧比对，说明证据边界。

## 检查实际采用的运动

先看首、中、尾及关键帧，再连续检查整个使用区间。可用全帧索引与连续联系表覆盖动作过程；联系表仅作 QC，不进入成片。检查脸、手、衣物、轮轴/器物、动作方向、背景与镜头是否连续。看不到的脚步、握持或细动作不可因为提示词要求过就宣称完成。

保留原生视频，另存裁边/截取/帧率转换后的采用版。按用户裁边范围保护主体；保持口播原速。普通非神经帧重采样需说明重复帧来源，不把它称为原生目标帧率或光流生成。模型声音与旁白无关时去掉该声轨。对派生后的整个区间再次检查，再按项目 VD 量表评分、记录缺陷和采用决定。

## 与已有长片合成

HyperFrames 工程先走 hyperframes 入口，保留全片唯一根 index.html；短段导出放在独立构建目录中，避免两个根合成导致重复音轨。视频由框架时钟控制，muted，显式声明 data-start、data-duration、data-media-start，不能让浏览器自主循环播放。

若只替换开场，可先实际检查旧成片视频流的关键帧。存在紧随改动区间的合适关键帧且编码兼容时，用 HyperFrames 渲染到该边界，后续视频流直接复制；整条混音原样复用。边界取自 ffprobe 实测，不能假设关键帧间隔。新旧编码不兼容时局部重编码或正常全片渲染，不强行无损拼接。

最终核对全片帧数、帧率、时长、章节与音轨。对保留正文可用全解码逐帧摘要证明像素和时间戳与旧版一致，明确引用旧视觉检查的实际范围；新增开场和接缝另查实际合成帧。检查烧入的字幕字形，而非只有 SRT 文件。全轨解码 PCM 一致性可以证明混音未改变，不能替代实际听感审查。

交付完整 MP4、字幕及可复查来源；保留旧版和原片。只有短开场生成完成不算整片任务结束。实际无法接收音频时据实保留听感待试听，不虚构全片听审通过。
